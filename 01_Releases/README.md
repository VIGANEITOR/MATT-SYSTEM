# Releases

Cada release entrega una capacidad general de la plataforma con un criterio de salida medible; el ámbito científico
es abierto (Brief Maestro v1.4 §3.0).

| Carpeta | Contenido |
|---|---|
| `01_Alcance` | Alcance detallado, mini-briefs y solicitudes de cambio |
| `02_Diseno` | Diseño y decisiones del release |
| `03_Desarrollo` | Seguimiento del desarrollo (el código vive en `07_Plataforma/` y `08_Programas/`) |
| `04_Verificacion_QA` | Evidencias de compuertas e informe de QA |
| `05_Entregables` | Paquete de traspaso al siguiente release e informe de cierre |
| `06_Feedback` | Registro de feedback del release |

**Continuidad:** un release solo se inicia cuando el anterior cumplió su criterio de salida y entregó su paquete de
traspaso (§3.5). **Mejora:** el feedback ajusta el alcance de los releases futuros; los liberados se corrigen con
versiones Rn.x (§3.6).
